# MPA 架構重構 - 視覺化流程參考文件

本文檔旨在為 `mp3.html` 從單頁應用 (SPA) 重構為多頁應用 (MPA) 提供視覺化參考。以下內容詳細記錄了應用程式在各個主要功能模組中的使用者操作流程，並附上對應的 UI 狀態螢幕截圖。

所有截圖均由 `e2e_comprehensive_ui.spec.js` 自動化測試腳本在模擬模式下產生。

---

## 流程一：本機檔案轉錄

此流程展示了使用者從上傳本機音訊檔案到預覽轉錄結果的完整過程。

1.  **上傳檔案與啟動**
    -   使用者在「本機檔案轉錄」分頁選擇了 "base" 模型，並上傳了一個名為 `mock_upload.txt` 的檔案。
    -   此時，「開始處理」按鈕變為可用狀態。使用者點擊該按鈕。
    -   **結果**: 一個新任務出現在下方的「處理中任務」列表中。
    -   **截圖**: `01_local_file_task_created.jpg`

2.  **任務完成**
    -   後端模擬伺服器處理完成後，任務狀態更新。
    -   **結果**: 任務從「處理中」列表消失，並出現在「已完成任務」列表中，同時顯示「預覽」和「下載」按鈕。
    -   **截圖**: `02_local_file_task_completed.jpg`

3.  **預覽結果**
    -   使用者點擊已完成任務上的「預覽」按鈕。
    -   **結果**: 一個包含模擬轉錄稿內容的 Modal 彈出視窗成功顯示。
    -   **截圖**: `03_local_file_preview_modal.jpg`

## 流程二：媒體下載器

此流程展示了使用者使用媒體下載器功能下載一個影片的過程。

1.  **提交下載任務**
    -   使用者切換到「媒體下載器」分頁，輸入一個 YouTube 網址，並選擇下載「影片」。
    -   使用者點擊「開始下載」按鈕。
    -   **結果**: 一個新的下載任務出現在「下載佇列與歷史紀錄」列表中。
    -   **截圖**: `04_downloader_task_created.jpg`

2.  **下載完成**
    -   後端模擬伺服器處理完成後，任務狀態更新為「已完成」。
    -   **結果**: 任務項目旁出現了可操作的按鈕（如預覽、修改名稱、下載等）。
    -   **截圖**: `05_downloader_task_completed.jpg`

## 流程三：YouTube 轉報告

此流程展示了最複雜的業務邏輯：使用 Gemini AI 分析 YouTube 影片並生成報告。

1.  **提交分析任務**
    -   使用者切換到「YouTube 轉報告」分頁，輸入並儲存了有效的 API 金鑰。
    -   接著，輸入一個 YouTube 網址，並點擊「分析影片」按鈕。
    -   **結果**: 一個新的分析任務出現在「處理中任務」列表中。
    -   **截圖**: `06_youtube_task_created.jpg`

2.  **分析完成**
    -   後端模擬伺服器完成分析後，任務狀態更新。
    -   **結果**: 「處理中」的任務消失，一個新的報告項目出現在「YouTube 報告瀏覽區」，其中包含了影片標題和操作按鈕。
    -   **截圖**: `07_youtube_report_item.jpg`

3.  **預覽分析報告**
    -   使用者點擊報告項目上的「預覽」按鈕。
    -   **結果**: 一個 Modal 彈出視窗成功顯示，其中透過 IFrame 載入了模擬的 HTML 報告內容。
    -   **截圖**: `08_youtube_report_preview.jpg`
